== Bug 修复 1:同步失败 toast 显示具体原因 ==

问题:用户点"同步文章"后,只能看到"同步部分完成:成功 X,失败 Y"通用汇总
  不知道每个失败订阅源的具体原因(网络超时 / HTTP 503 / Feed 格式错误等)
根因:后端 sync-service.ts 的 diagnosticErrorMessage 正确返回具体错误文本到
  SyncResult.error 字段,但前端 handleSyncAll 只取了 r.ok 布尔值,丢弃了 r.message

修改:
- App.tsx handleSyncAll:新增 failedFeedErrors 数组收集 { name, error }
  失败 toast 改为多行格式:
    同步部分完成:成功 X,失败 Y。未成功同步的订阅源已用红点标出
    · 失效订阅源A:网络超时 [HTTP_TIMEOUT]
    · 失效订阅源B:服务器错误 [HTTP_BAD_STATUS] 503
  失败源 > 5 个时只显示前 5 条 + "...还有 N 个"避免 toast 过长
- Toast.css:加 white-space: pre-line 让 \n 真正换行(toast 之前默认会折叠空白)
- 成功时行为不变 — 仍显示"同步完成:N/N 成功"
- 侧栏红点逻辑不受影响(failedFeedIds 照常设置)

后端链路已就绪无需修改:
- sync-service.ts:145-149 diagnosticErrorMessage 写入 SyncResult.error
- ipcDataSource.ts:212 syncFeed 返回 FeedSyncOutcome 含 message/error 字段

== 改进:列表滚动到底自动加载 ==

问题:用户需点"加载更多"按钮才能看下一批 50 篇
修改:ArticleList 加 IntersectionObserver 自动追加
- 末尾加 1px 哨兵 div(ref={sentinelRef},data-testid="article-list__sentinel")
- useEffect 创建 IntersectionObserver 监听哨兵
  root = ul 滚动容器,rootMargin=200px 提前触发
  isIntersecting + hasMore + !loadingMore → 自动调 onLoadMore
- 保留"加载更多"按钮作为兜底(observer 失效 / 键盘 a11y 时仍可手动触发)
  smoke:search-pagination 的 data-testid="article-list__load-more" 探针仍工作
- deps 包含 hasMore / loadingMore / articles.length:
  状态变化时重新 attach observer,避免 stale callback
- onLoadMore 用 ref 缓存(onLoadMoreRef),保证 observer callback 用最新引用
  防止 stale closure 拿到旧的 disabled 状态
